# 사진 전달

`VITE_PHOTO_CDN_BASE_URL`에 사진 CDN의 HTTPS origin을 지정한다. API의 검증된 `cdn_path`와
결합하며 임의 외부 URL, 쿼리, 문서/원문 경로는 허용하지 않는다. 개발 격리 테스트만 loopback HTTP를 허용한다.
목록 대표사진과 상세는 같은 URL을 사용한다. 상세는 처음 3장, 더 보기마다 3장씩 렌더링한다.
`retry` 쿼리로 캐시를 분리하지 않는다. 장애 시 사용자 재시도로 같은 URL의 이미지 요소를 다시 생성한다.
CDN 실패를 API 원본으로 자동 우회하지 않는다. 브라우저 지연 로딩은 유지한다.

## 대표사진과 표시 순서

검색 목록과 상세 갤러리는 `goods-photo-display.ts`의 공통 선택 규칙을 사용한다.
해당 물건의 유효한 사진 경로 중 관련사진(`000245`) → 전경도(`000241`) → 위치도(`000244`)
순으로 선택하고, 이 유형들이 없으면 첫 유효 사진을 사용한다. 같은 유형에서는 API 순서를 따른다.
인사이트옥션과 비교한 5개 물건은 모두 첫 관련사진이 대표사진과 일치했다.
관련사진이 없는 경우의 대체 순서는 기존 앱 정책이다.

상세는 선택한 대표사진 한 장만 맨 앞으로 옮기고 나머지 사진은 API 순서를 유지한다.
원본 응답과 DB의 사진 순서는 변경하지 않는다. 표시 가능한 후보가 없으면 기존 순서를 유지한다.
선택에는 이미 받은 분류 코드와 경로만 사용하며, 사진 판별을 위한 다운로드나 추가 API 요청은 없다.
분류 기반 선택이므로 사진 내용이나 화질까지 보장하지는 않는다.

빌드 시 CDN 설정이 필요하며 설정이 비어 있으면 기존 상대 API 경로를 사용한다.

로컬 앱은 프런트 전용 `.env.local`에서 CDN 주소를 지정한다. 현재 사진 origin은
`https://d35ek1gatke53l.cloudfront.net`이며, 배포 환경에서도 동일 변수를 빌드 전에 설정한다.
백엔드는 `cdn_path`를 반환해야 한다. 공용 크롤러 환경변수나 DB 변경은 필요하지 않다.
미디어 E2E는 CDN 설정을 명시적으로 비우며, 비용 E2E는 로컬 합성 CDN 주소로 덮어써 실제 AWS에 접속하지 않는다.
